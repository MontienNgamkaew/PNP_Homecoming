# เว็บไซต์ตัวอย่างคืนสู่เหย้า — Tailwind + daisyUI

เว็บไซต์ในเครื่อง ใช้ QR ตัวอย่าง ยังไม่เปิดรับชำระเงินจริง ข้อมูลรายการและการตั้งค่าบันทึกใน SQLite

## เปิดตัวอย่าง
จากโฟลเดอร์โปรเจกต์หลัก:

```sh
PORT=8081 python3 server.py
```

เปิด http://127.0.0.1:8081/

## แก้ไขธีม
- styles/theme.css: Tailwind utilities, daisyUI theme `homecoming` และรูปแบบเฉพาะงาน
- theme.css: CSS ที่ build แล้วและเว็บโหลดจริง ไม่ต้องใช้ CDN หรือ JavaScript compiler ของ Tailwind บนเบราว์เซอร์
- app.js: หน้าจอจองโต๊ะ จองเสื้อ แจ้งโอน และผู้ดูแล เชื่อมต่อ API ของ server.py
- styles/approved-v2.css / style.css: เก็บ CSS ฉบับก่อนย้ายไว้เป็นหลักฐาน เว็บฉบับใหม่ไม่โหลดไฟล์เหล่านี้

ในโฟลเดอร์ prototype:

```sh
npm ci
npm run build:css
```

ระหว่างแก้ไขใช้ `npm run watch:css` หลังแก้ class ใน HTML/JS ต้อง build CSS ใหม่

ใช้ Tailwind CSS 4.3.4 และ daisyUI 5.7.50 ตาม package-lock.json
ใช้ prefix `ui-` สำหรับ daisyUI เพื่อไม่ชนกับชื่อ class ผังโต๊ะและหน้าจำลองเดิม
ฟอนต์ Noto Sans Thai โหลดจาก Google Fonts โดยมี Thonburi และ sans-serif สำรอง

## ตรวจแล้ว
- build CSS และตรวจไวยากรณ์ JavaScript ผ่าน
- หน้าจอมือถือ 390px: ฟอร์มเสื้อ แสดงที่อยู่เมื่อเลือกไปรษณีย์ และยอด 2 ตัวรวมส่ง 648 บาท
- ผังโต๊ะ 100 โต๊ะ เลือก 1 โต๊ะเป็น 2,500 บาท เปิดหน้าชำระเงินตัวอย่างได้
- หน้าตั้งค่าผู้ดูแลแสดงฟอร์มราคา วันที่ และ QR แยกประเภท
- ผังโต๊ะเลื่อนในกรอบ โดยหน้าเว็บไม่ล้นแนวนอนที่ 390px

ระบบบันทึกรายการและการตั้งค่าถาวร มีการเข้าสู่ระบบและป้องกันโต๊ะชนกันที่เซิร์ฟเวอร์ ส่วนการตรวจสลิปต้องทำโดยผู้ดูแล ยังไม่ตรวจรายการธนาคารอัตโนมัติ

## ดีไซน์ v4
ปรับหน้าหลักเป็นน้ำเงินเข้ม–ขาว–ทอง ใช้โปสเตอร์ฉบับจริงแบบแสดงเต็มภาพ แถบวันและสถานที่ การ์ดกิจกรรม 4 รายการ และส่วนแสดงเสื้อที่ระลึก พร้อมเปลี่ยนสีปุ่มและหัวข้อหน้าภายในให้เป็นธีมเดียวกัน
ตรวจภาพที่ความกว้าง 390px และ 1280px แล้ว หน้ามือถือไม่ล้นแนวนอน รูปประกอบโหลดครบ
ภาพหน้าจอ: mobile-redesign-v4.png และ website-redesign-v4.png
เก็บธีมก่อนหน้าไว้ใน styles/theme-v3.css

## ตั๋วอิเล็กทรอนิกส์
หลังส่งจองโต๊ะ ให้กด “รับตั๋วและเก็บรหัสติดตาม” แล้ว “ดูและดาวน์โหลดตั๋วเข้างาน” หรือใช้หน้าติดตามสถานะเพื่อรับตั๋วอีกครั้ง ไฟล์ PNG ระบุเลขอ้างอิง ชื่อผู้จอง โต๊ะ จำนวนที่นั่ง และสถานะ ณ เวลาดาวน์โหลด รหัสติดตามส่วนตัวและเบอร์โทรไม่ถูกใส่ในตั๋ว

รายการ pending/rejected ไม่ใช่สิทธิ์เข้างาน รายการ confirmed ใช้แสดงให้เจ้าหน้าที่ค้นเลขอ้างอิงในระบบก่อนเข้างาน ปัจจุบันยังไม่มีการสแกนเช็กอินอัตโนมัติหรือการป้องกันใช้ตั๋วซ้ำแบบสแกน

โมดูลสร้าง PNG: assets/ticket.js API: POST /api/ticket (ref+token) รีสตาร์ต server.py หลังเปลี่ยน backend

## ตั๋วรับเสื้อ
ตั๋วขนาดกะทัดรัด 900 × 1040 px ในรายการทั่วไป ใช้กราฟิกเขียว–ทองเดียวกับตั๋วโต๊ะ เพิ่มความสูงเมื่อมีหลายไซซ์/ชื่อยาว ข้อมูลประกอบด้วยเลขอ้างอิง ชื่อ ไซซ์และจำนวนรวม ยอดชำระ วิธีรับ และสถานะชำระเงิน

รับตั๋วได้หลังส่งรายการจากปุ่ม “รับตั๋วและเก็บรหัสติดตาม” หรือค้นผ่านหน้าติดตามแล้วกด “ดูและดาวน์โหลดตั๋วรับเสื้อ” รายการรับเองใช้ยื่นให้เจ้าหน้าที่ตรวจหลังยืนยันชำระเงิน รายการไปรษณีย์ระบุวิธีรับและชื่อผู้รับโดยไม่พิมพ์ที่อยู่/เบอร์โทร/รหัสติดตามลงภาพ

ยังไม่มีการลงบันทึกส่งมอบเสื้อหรือสแกนรับเสื้อซ้ำอัตโนมัติ เจ้าหน้าที่ตรวจเลขอ้างอิงกับรายการก่อนส่งมอบ

## โปสเตอร์สลับภาพ
ผู้ดูแล → โปสเตอร์: ใส่ชื่อ เลือก JPG/PNG/WebP ไม่เกิน 5 MB แล้วกดเพิ่ม หรือลบภาพจากรายการ รูปบันทึกใน SQLite และแสดงสลับทุก 5 วินาทีบนหน้าแรก มีปุ่มเลื่อนเองและหยุดสลับ ภาพจะแสดงเต็มสัดส่วนโดยไม่เพิ่มความสูงแบนเนอร์เดิม

API: GET /api/posters, GET /api/posters/{id}/image, POST /api/admin/posters (action add/delete; ต้องล็อกอิน) โมดูล assets/posters.js
การลบจะนำภาพออกจากรายการและปิด URL สาธารณะ เก็บแถวเดิมในฐานข้อมูลเพื่อรักษาประวัติ ไม่กลับมาเองเมื่อรีสตาร์ต
โปสเตอร์เริ่มต้น 2 แบบ: poster-compact-v1.png และ poster-celebration-v2.png
การเปลี่ยน server.py ต้องรีสตาร์ตเซิร์ฟเวอร์เดิมเพื่อโหลด API ใหม่

ผู้ดูแล → ข้อความแบนเนอร์: แก้หัวข้อ ข้อความสองบรรทัด ข้อความสีทอง และคำบรรยาย พร้อมขนาดตัวอักษรแยกคอมพิวเตอร์/มือถือและพรีวิวก่อนบันทึก ขนาดข้อความหลัก 12–64 px ส่วนหัวข้อ/คำบรรยาย 12–28 px แบนเนอร์ขยายตามเนื้อหาเพื่อไม่ตัดข้อความ

ตรวจสถานะด้วยเบอร์โทรที่แจ้งรายการ + เลขอ้างอิง ส่วนตั๋วใช้ลิงก์ส่วนตัวหรือรหัสตั๋วเดิมที่หน้า #ticket ควรเก็บลิงก์เป็นส่วนตัว เบอร์โทรเพียงอย่างเดียวหรือเบอร์โทรกับเลขอ้างอิงใช้เปิดตั๋วไม่ได้ การค้นหาสถานะรองรับรูปแบบเบอร์ +66 และจำกัด 20 ครั้งต่อ IP ใน 15 นาที โดยไม่แสดงชื่อ ที่อยู่ สลิป หรือรหัสส่วนตัวในผลค้นหา

แอดมินออกลิงก์ตั๋วใหม่ได้จากรายการโต๊ะจีน/เสื้อ โดยตรวจตัวตนและระบุเหตุผลก่อน รหัสเดิมถูกยกเลิกทันที ระบบเก็บเฉพาะ hash ของรหัสใหม่ พร้อมประวัติเหตุผล แต่ไม่เก็บรหัสจริงไว้ดูย้อนหลัง ควรคัดลอกลิงก์ใหม่ส่งผู้จองก่อนปิดหน้าต่าง ไม่เปลี่ยนยอดเงินหรือสถานะ และไม่อนุญาตให้ทำกับรายการยกเลิกหรือตั๋วที่บันทึกใช้แล้ว
