# แจ้งโอนเงินบริจาค — คืนสู่เหย้าศิษย์เก่า การอาชีพพนมไพร ครั้งที่ 2

ต้นแบบภาษาไทยพร้อมโค้ดฝั่งเว็บและเซิร์ฟเวอร์ สำหรับงานทอดผ้าป่าเพื่อการศึกษา ในโอกาสครบรอบ 30 ปีแห่งการก่อตั้งวิทยาลัยการอาชีพพนมไพร วันที่ 2 มกราคม 2570 ณ วิทยาลัยการอาชีพพนมไพร จังหวัดร้อยเอ็ด

**สถานะ: ต้นแบบในเครื่อง ยังไม่เปิดใช้งานรับข้อมูลจริง** ใช้ข้อมูลสมมติในการทดสอบ โลโก้ยังเป็นตัวอักษรชั่วคราว ไม่ใช่โลโก้งานฉบับอนุมัติ ไม่มีการสมมติบัญชีธนาคารหรือข้อมูลติดต่อ

## เริ่มใช้งาน

ต้องมี Python 3.9 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วรัน:

```sh
python3 server.py
```

เปิด http://127.0.0.1:8080 สำหรับหน้าแจ้งโอน และ http://127.0.0.1:8080/admin สำหรับหน้าผู้ดูแล การแจ้งโอนใช้ได้ทันที ส่วนการเข้าสู่ระบบผู้ดูแลถูกปิดไว้จนกว่าจะตั้งรหัสผ่านอย่างน้อย 16 ตัวอักษร

หากต้องการทดลองผู้ดูแล ให้หยุดเซิร์ฟเวอร์ด้วย Control+C แล้วรันด้วย zsh/bash (พิมพ์รหัสผ่านเอง ข้อความที่พิมพ์จะไม่แสดง):

```sh
read -s 'ADMIN_PASSWORD?ตั้งรหัสผ่านผู้ดูแลอย่างน้อย 16 ตัวอักษร: '
export ADMIN_PASSWORD
python3 server.py
```

รหัสผ่านไม่ถูกเขียนลงไฟล์ ไม่ควรแชร์กับผู้ใช้ทั่วไป เซสชันมีอายุ 1 ชั่วโมงและหมดเมื่อรีสตาร์ต ข้อมูลรายการยังอยู่ใน `data/donations.sqlite3` ส่วน `DATA_DIR` และ `PORT` ปรับผ่านตัวแปรแวดล้อมได้

## สิ่งที่ทดลองได้

- กรอกชื่อ จำนวนเงินทศนิยมไม่เกิน 2 ตำแหน่ง วันเวลาไทย ช่องทางติดต่อไม่บังคับ แนบ JPG/PNG/PDF ไม่เกิน 5 MB
- อ่านข้อมูลสรุป กลับไปแก้ไข และยืนยันส่ง ระบบให้เลขอ้างอิงกับรหัสติดตามที่ดาวน์โหลดเป็นข้อความได้ เก็บรหัสอย่างปลอดภัย เพราะดูซ้ำไม่ได้
- ทุกยอดเริ่มรอตรวจสอบ ติดตามด้วยเลขอ้างอิงและรหัสส่วนตัวเท่านั้น ไม่คืนชื่อ ยอดเงิน หรือสลิปแก่บุคคลทั่วไป
- ผู้ดูแลดูรายการ ค้นหา ดาวน์โหลดสลิป อนุมัติ ไม่ผ่าน หรือคืนรอตรวจสอบได้ มีบันทึกประวัติการเปลี่ยนสถานะในตาราง audit
- ยอดรวมผู้ดูแลนับเฉพาะรายการที่อนุมัติและโหลดมา (สูงสุด 500 รายการล่าสุด) ไม่มีรายชื่อหรือยอดรวมบริจาคสาธารณะ ไม่ออกใบเสร็จทางบัญชี

## โครงสร้างระบบ

```text
public/index.html + app.js  → POST /api/donations → ตรวจข้อมูล/จำกัดคำขอ/ตรวจไฟล์ซ้ำ
                                                  ↓
                                         SQLite ส่วนตัว + สลิป BLOB
                                                  ↑
public/admin.html + admin.js → เซสชันผู้ดูแล → รายการ/ดาวน์โหลด/สถานะ + audit

ผู้แจ้ง → POST /api/status (เลขอ้างอิง + รหัสติดตาม) → เฉพาะสถานะ
```

รหัสติดตามเก็บฝั่งเซิร์ฟเวอร์เป็น SHA-256 ข้อมูลไม่ถูกเก็บใน localStorage ใช้ SQL แบบมีพารามิเตอร์ ตรวจ Origin ฝั่งเซิร์ฟเวอร์ เซสชันใช้คุกกี้ HttpOnly/SameSite=Strict มี CSP และ no-store สลิปถูกเก็บนอกโฟลเดอร์สาธารณะ ดาวน์โหลดได้เฉพาะผู้ดูแลในรูปแบบ attachment ตรวจชนิดจากลายเซ็นไฟล์เบื้องต้น ไม่เชื่อชื่อหรือนามสกุลไฟล์ ห้าม SVG/HTML และตรวจสลิปซ้ำด้วย SHA-256 โดยไม่เปิดเผยเจ้าของเดิม

ป้องกันสแปมเบื้องต้นด้วยช่อง honeypot และจำกัดคำขอต่อ IP: ส่ง 10 ครั้ง/15 นาที เข้าสู่ระบบ 10 ครั้ง/15 นาที ติดตาม 60 ครั้ง/15 นาที การตรวจไฟล์ซ้ำจับได้เฉพาะไฟล์ที่มีเนื้อหาเหมือนกันทุกไบต์ ยังไม่ตรวจ OCR หรือเลขธุรกรรมธนาคาร จึงต้องตรวจรายการเดินบัญชีโดยผู้ดูแล

## ก่อนเปิดใช้งานจริง

1. รับไฟล์โลโก้และสีฉบับอนุมัติ รวมทั้งข้อมูลบัญชี/ติดต่อที่ผู้จัดงานยืนยัน หากจะเพิ่มในเว็บ
2. ย้ายไปบริการรองรับ HTTPS, จัดเก็บสลิปแบบ private object storage พร้อม quarantine และสแกนมัลแวร์ก่อนผู้ดูแลเปิดไฟล์ ลายเซ็นไฟล์เบื้องต้นไม่ใช่การรับรองไฟล์ปลอดภัย
3. เปลี่ยนการยืนยันตัวตนผู้ดูแลเป็นบัญชีรายบุคคลและ MFA/บทบาท พร้อมบันทึกผู้ตรวจแต่ละรายการ ต้นแบบนี้ใช้รหัสผ่านร่วมและบันทึกเฉพาะเวลา/สถานะ ไม่มีชื่อผู้อนุมัติ
4. เพิ่ม CAPTCHA ที่ตรวจฝั่งเซิร์ฟเวอร์, ขีดจำกัดพื้นที่จัดเก็บ, IP proxy ที่เชื่อถือได้, กลไกตรวจธุรกรรมซ้ำ และรายการแบบแบ่งหน้าสำหรับข้อมูลเกิน 500 รายการ
5. กำหนดผู้ควบคุมข้อมูล นโยบายความเป็นส่วนตัว ระยะเวลาเก็บ ลบข้อมูล/สำรอง/กู้คืน และช่องทางรับคำขอจากเจ้าของข้อมูลที่ยืนยันแล้วก่อนใช้จริง ข้อความรับทราบในต้นแบบยังไม่ใช่นโยบายฉบับสมบูรณ์
6. ตั้ง HTTPS และ `SECURE_COOKIE=1` เมื่อปรับใช้หลัง reverse proxy ต้นแบบรับเฉพาะ loopback และยังไม่พร้อมนำออกอินเทอร์เน็ตโดยตรง Origin หลัง proxy ต้องปรับให้ใช้ค่าที่กำหนดไว้แน่นอน

SQLite ในต้นแบบไม่ได้เข้ารหัสที่ระดับแอป ต้องควบคุมสิทธิ์เครื่องและสำรองข้อมูลอย่างปลอดภัย `data/` ถูกยกเว้นจาก Git แล้ว ไม่ควรรวมข้อมูลจริงในไฟล์ส่งมอบ

## ตรวจสอบโค้ด

```sh
python3 -m unittest discover -s tests -v
node --check public/app.js
node --check public/admin.js
```

ทดสอบผ่านเซิร์ฟเวอร์จริงกับฐานข้อมูลชั่วคราว: ส่งรายการ → กันไฟล์ซ้ำ → ติดตามส่วนตัว → ปฏิเสธผู้ไม่มีสิทธิ์ → ผู้ดูแลอนุมัติ → ติดตามสถานะที่เปลี่ยน → ออกจากระบบ รวมถึงชนิดไฟล์ไม่ถูกต้อง จำนวนเงินผิดรูปแบบ และการจำกัดการล็อกอิน
